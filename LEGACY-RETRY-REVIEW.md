# Legacy Retry timing review

Reviewed before implementing this update: the extracted Launcher 1.8.34 Settings/Timing UI and main process, and the old Spain extension's countdown logic. The Spain countdown.js in 1.8.24 and 1.8.34 is byte-identical, SHA-256 8c2ddb256d117f6285a154bda8f2d76bb59cad966741a8ccb2d7da85c386ee8e. Existing static string-decoding output was used to trace those functions; no old application or live BLS request was executed for this review.

Auto Retry Calendar uses autoSlotRedirect and redirectDelay: on entering Retry, a countdown decreases once per second, then navigates to the saved target URL. The old built-in fallback Delay is 7 seconds. Attempts/max action are separate settings.

Auto Retry Calendar /Sec uses autoRedirectOnSec plus autoSubmitSec (0–59) and autoSubmitMs (0–999). It targets that second/millisecond position every minute, using the computer clock. The old default is second 0 and millisecond 500. It checks during the preceding second and sets a timeout for the remaining milliseconds. This is different from a relative Delay and does not specify a full initial hour. On initial Retry entry, /Sec takes priority if both legacy flags are true; that is not a reliable mutually exclusive mode selector.

The legacy Launcher Timing tab has Retry Calendar Scheduler /delay: HH:mm:ss.SSS, per-profile delay in milliseconds, Set and Stop. Its main process checks readiness 500 ms before a scheduled send, staggers ready profiles by index × delayMs, and also broadcasts the legacy submit command. getNextFireTime advances the target by minutes after it has passed. Stop clears the main/pre-check timers but does not retain every already queued per-profile timeout handle. These details were reviewed rather than copied blindly.

Confirmed new behavior: use a full local-device time for the first run, then repeat on a fixed 60-second cadence. A new past start time means tomorrow; restoring a saved running anchor continues at the next future minute and skips missed ticks. Auto Retry Calendar uses the existing Delay; Auto Retry Sec uses the Timing schedule. Enabling either disables the other. Timing profile delay is staggering between profiles, not the retry interval. Stop invalidates the clock generation, clears queued profile dispatches and cancels matching in-flight checks. Verification/cooldown/attempt guards remain in place.
